# Матрица устройств

Результаты запусков на реальных телефонах (спецификация: FR-013, FR-023). Каждая запись — дата, устройство, версия библиотеки, что запускали.

Как повторить на другом устройстве:

```bash
./gradlew :devicetrust:assembleDebugAndroidTest
adb install -r -t devicetrust/build/outputs/apk/androidTest/debug/devicetrust-debug-androidTest.apk
adb shell am instrument -w -e class org.wolpmessenger.devicetrust.LockBindingProbeDeviceTest \
  -e dtProbe env|create|use|cleanup org.wolpmessenger.devicetrust.test/androidx.test.runner.AndroidJUnitRunner
adb logcat -d -s System.out:I | grep DT-PROBE
```

`create` — при разблокированном экране; `use` — в каждом состоянии. Ключи опыта живут до `cleanup` или удаления тестового пакета.

### Привязка ключа Keystore к блокировке экрана (история 2)

Ключи AES-256-GCM, уровень TEE. «Заблокирован» — `deviceLocked=true` через 5 с после выключения экрана.

| Ключ | Создание | Экран разблокирован | Экран заблокирован |
|---|---|---|---|
| без привязки (как `dt.vault` сейчас) | да | работает | **работает** |
| `setUnlockedDeviceRequired(true)` | да | работает | отказ: `Device locked` (код −72) |
| `setUserAuthenticationRequired`, 30 с, PIN или биометрия | да, `hwEnforced=true` | отказ `UserNotAuthenticatedException`, пока с ввода PIN прошло больше 30 с | отказ `UserNotAuthenticatedException` |
| оба требования | да, `hwEnforced=true` | отказ `UserNotAuthenticatedException` | отказ: `Device locked` |

Выводы:

- Ключ без привязки расшифровывает при заблокированном экране — подтверждено на устройстве.
- `setUnlockedDeviceRequired` на A37 работает: отказ приходит от системного Keystore (`keystore2`), а не от приложения.
- Требование аутентификации исполняет железо (`hwEnforced=true`), но с окном 30 с ключ недоступен почти всегда — для хранилища мессенджера без запроса PIN внутри приложения он не годится.

После разблокировки экрана владельцем и смены PIN на другой (ключи созданы при прежнем PIN):

| Ключ | Результат |
|---|---|
| без привязки | работает, старый шифртекст расшифрован |
| `setUnlockedDeviceRequired(true)` | снова работает, **старый шифртекст расшифрован** — смена PIN ключ не уничтожает |
| с аутентификацией 30 с (оба варианта) | шифрование проходит сразу после разблокировки экрана PIN — разблокировка экрана считается аутентификацией |

После добавления и удаления отпечатка:

| Ключ | Результат |

| с аутентификацией 30 с (оба варианта) | `UserNotAuthenticatedException` — истекло окно 30 с; ключи не помечены как уничтоженные (они допускают PIN, поэтому смена биометрии их не трогает) |

### Двухключевое хранилище библиотеки на настоящем Keystore (история 2)

Фазы `vault-create`, `vault-use`, `vault-wipe` того же опыта. Сначала создано хранилище старого вида (один ключ) с данными E2EE, затем перенос.

| Шаг | Экран разблокирован | Экран заблокирован (новый процесс) |
|---|---|---|
| перенос старого хранилища (`migrate`) | выполнен, состояние ключей `PRESENT` | не проверялось на устройстве (в JVM-тестах: не выполняется, всё работает как раньше) |
| расшифровка данных E2EE, созданных до переноса | работает | `Locked` |
| шифрование E2EE | работает | `Locked` |
| расшифровка `PUSH_KEY`, шифрование `NAMES` | работает | **работает** |
| состояние ключей после отказов | `PRESENT` | `PRESENT` — ничего не уничтожено |

Не проверено на устройстве: создание двухключевого хранилища с нуля (`provision`; те же операции Keystore, что и в переносе), удаление ключа E2EE из памяти по выключению экрана в работающем процессе, снятие блокировки экрана.
